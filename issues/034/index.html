MODEL · 公开预览Mistral · 2026.10.06 · 12:00 UTC

Mistral Large 4 开放 API 预览，权重计划月底发布

Mistral Large 4 enters API preview; weights are planned for month-end

Mistral 发布 Large 4 公开预览，支持多模态输入。官方模型文档列出1.05万亿总参数、490亿激活参数及100万 token 上下文。公告明确权重计划月底发布，因此当前不能写成权重已经开放。其编程、视觉与工作流表现包含发布方评测与所引用榜单，不能视为所有实际任务的效果保证。

Mistral opens a public API preview of Large 4 with multimodal input. Its model documentation lists 1.05 trillion total parameters, 49 billion active parameters and a one-million-token context. The announcement schedules weights for month-end; they should not be described as already available. Coding, vision and workflow claims combine publisher evaluations and cited rankings, rather than guarantees for every real task.

ON-DEVICE · 模型发布Google DeepMind · 2026.10.06 · 16:00 UTC

EmbeddingGemma 2 将文字、图像与音视频映射到统一向量空间

EmbeddingGemma 2 brings multimodal embeddings to local devices

Google 发布7.4亿参数的 EmbeddingGemma 2，采用 Apache 2.0 许可，可将文字、代码、图像、音频和视频用于跨模态检索。模型采用模块化设计，纯文字路径为2.7亿参数。Google 报告量化版本在 Pixel 11 Pro 上的特定内存测量；这些属于厂商测试，不能外推到任意手机，也不意味着本地运行的应用天然不会上传数据。

Google releases the 740-million-parameter EmbeddingGemma 2 under Apache 2.0 for retrieval across text, code, images, audio and video. Its modular text-only path uses 270 million parameters. Google reports device-specific memory measurements for quantized versions on Pixel 11 Pro. These are vendor tests, not promises for every phone; local inference also does not automatically guarantee that an application never uploads data.

API · 公测OpenAI Developers · 2026.10.06 · 20:53 UTC

Decisions API 进入公测，面向条件判断、选择与评分

Decisions API enters beta for predicates, choices and scores

OpenAI 宣布由 GPT-6 Luna 驱动的 Decisions API 进入公测，接受文字和图像，返回条件概率、预设选项或数值评分。它把任务限定在预定义输出，适用于路由与分类等工作。公告声称相对通过 Responses API 使用 GPT-6 Luna 最多快10倍；这是厂商性能主张，本刊未独立复测，输出置信度也不能直接当作正确性保证。

OpenAI launches the GPT-6 Luna-powered Decisions API in public beta. It accepts text and images and returns predicate probabilities, predefined choices or numeric scores for tasks such as routing and classification. The announcement claims up to 10× faster decisions than GPT-6 Luna through the Responses API. This is a vendor performance claim, not independently reproduced here; a confidence score is not a correctness guarantee.

SCIENCE · 研究材料OpenAI · 2026.10.06 · 官方发布日

OpenAI 公开模型生成的数学材料，附部分 Lean 形式化证明

OpenAI publishes model-generated mathematics with Lean proof artifacts

OpenAI 将内部模型产出的数学结果、修订规则及部分 Lean 形式化证明放入公开仓库，并披露10份推理摘要与计算量估计。发布不等于全部成果已经同行评审。相关独立顾问组同日明确：其建议不构成对成果影响或研究过程的背书，数学共同体仍需评估。这批材料首先提供了可检查的研究对象，而非统一验证结论。

OpenAI publishes mathematical results from an internal model, revision protocols and Lean formalizations for many proofs, alongside ten reasoning summaries and compute estimates. Publication does not mean every result has passed peer review. The independent advisory group states that its advice does not endorse the results’ impact or the process, and that the mathematical community must assess the work. These are inspectable research artifacts, not a blanket verification.

COMPUTER USE · 合作研究OpenAI / Ironclad · 2026.10.06 · 官方发布日

OpenAI 与 Ironclad 用合同流程研究专业软件操作

OpenAI and Ironclad study agents working in professional software

双方把合同配置、审批规则等流程转成11项研究任务。OpenAI 报告 GPT-6 Astra 的平均评分为55.0%，GPT-5.6 Sol 为41.6%；每次尝试的估计时间分别为19.2与37.0分钟。数字仅覆盖这组合作研究，时间是模拟估计，并非实测客户节省时间。该研究强调检查最终流程是否满足要求，也明确仍需人工监督。

The collaboration turns contracting configuration and approval workflows into eleven research tasks. OpenAI reports mean rubric scores of 55.0% for GPT-6 Astra and 41.6% for GPT-5.6 Sol, with estimated times of 19.2 and 37.0 minutes per attempt. These results cover this research set; times are simulated estimates, not measured customer savings. The work emphasizes checking complete workflows against requirements and retaining human oversight.

EVALUATION · 研究访谈Microsoft Research · 2026.10.06 · 16:19 UTC

微软研究访谈：多轮协作与长任务需要更贴近使用场景的评测

Microsoft Research discusses evaluation beyond single-turn benchmarks

Jennifer Neville 在新发布的研究访谈中讨论多轮对话、协作环境和长任务里的失败，以及从数据与实际需求出发设计评测的方法。节目回顾相关研究，而不是宣布当日发布了一个新模型或统一性能提升。其要点是：单次问答的高分不足以说明智能体能在不断补充条件的真实工作中持续做对。

In a newly published interview, Jennifer Neville discusses failures in multi-turn conversation, collaborative settings and long-horizon tasks, and how to build evaluations around data and actual user needs. The episode revisits research rather than launching a new model or establishing a uniform performance gain. Its central lesson is that strong single-turn scores do not establish reliable work as requirements evolve over time.
