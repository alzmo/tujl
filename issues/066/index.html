Microsoft Agent Framework 1.25提高Python门槛，并收紧MCP与会话边界

Microsoft Agent Framework 1.25 raises the Python minimum and tightens MCP and session boundaries

Python版1.25.0要求Python 3.11或更高版本。维护方同时加入MCP目录默认100页、1000项的发现上限，以及框架管理请求的30秒默认超时；工作流执行器和会话绑定单一授权域。这些是含破坏性变更的发布说明，多用户部署仍须检查共享存储与自定义工具的权限。

Python 1.25.0 requires Python 3.11 or newer. Maintainers set default MCP discovery limits of 100 pages and 1,000 items per catalog, plus a 30-second timeout for framework-owned requests. Live workflow executors and sessions are bound to one authorization scope. These are breaking release changes; multi-user deployments still need to check shared storage and custom-tool permissions.

Xinference 4.2.0增加跨副本缓存共享、滚动重载与网页基准测试

Xinference 4.2.0 adds cross-replica caching, rolling reloads and browser-based benchmarks

Xinference 4.2.0的发布说明介绍Xavier跨副本兼容前缀缓存共享，并为受支持的vLLM与SGLang部署加入逐副本滚动重载。网页界面可测试吞吐量、首个令牌延迟及输出令牌耗时，导出JSON结果。减少重复预填充是维护方的功能描述，实际收益取决于模型、引擎与负载，尚无本刊独立实测。

Xinference 4.2.0 describes Xavier sharing compatible prefix caches across replicas, alongside rolling reloads for supported vLLM and SGLang deployments. Its Web UI can benchmark throughput, time to first token and time per output token, then export JSON results. Reduced repeated prefill is a maintainer-described capability; actual gains depend on the model, engine and workload and have not been independently tested by TUJL.

llama.cpp预发布加入CPU分担MoE缓存未命中与调参脚本

llama.cpp pre-release adds CPU handling of MoE cache misses and a tuning script

llama.cpp的b12191预发布允许将部分MoE缓存未命中的专家计算交给CPU，而非全部上传至设备。新增调参脚本会测试不同缓存容量与CPU分担比例，再建议配置。发布说明未给出适用于所有硬件的提速结论；这仍是预发布构建，应先在自己的模型与机器上验证。

The llama.cpp b12191 pre-release lets the CPU compute a share of MoE cache misses instead of uploading every missed expert to the device. A new tuning script tests cache sizes and CPU shares before recommending settings. The release does not establish a speedup across all hardware. This remains a pre-release build and needs validation on the intended model and machine.
