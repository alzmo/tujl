After a file is uploaded once with the Files API, its URI can be reused across turns and tool calls. The API lets the agent specify what parts of a file to inspect directly inside a function response. You can skim first with extracted text, low-resolution previews or transcripts, then spend high-resolution tokens only on the charts, dense layouts and frames that matter. Slicing can be done by range, layer, resolution and frame rate. The post also says that when model APIs only ingest whole files, agents often run LibreOffice, PDF renderers and ffmpeg inside the client harness; with this capability, a Files API URI can be passed on a user turn or inside a function_result, and the API slices, renders and tokenizes the file server-side.
