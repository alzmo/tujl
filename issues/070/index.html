browser-use 1.0.5 让同一次运行由用户自己的模型判分

browser-use 1.0.5 has the user's own model judge each run

browser-use 1.0.5 为正式发布。发布说明写明，每次运行结束后会再用用户自己的模型发一次低消耗请求，对照任务填写 result.judgement，字段包括 success、failure_reason、description、prompt_injection_detected、bot_block_or_captcha_detected 与 gotchas。judge_context= 用来传入判分标准，judge=False 可关闭；0.x 的 use_judge 与 ground_truth 重新可用。判分会看到运行轨迹、最后的截图和最终页面，除非 use_vision=False。站点拒绝输入、报错、拦截或限速时，即使运行被判成功也会写下 gotchas，例如表单要求电话号码使用 (###) ###-####。说明给出 13 次真实运行、每次判 3 遍的结果：站点有抵触的 15 次判分里都写了 gotchas（此前为 15 次中的 6 次），干净运行的 24 次判分里有 2 次写了 gotchas，成功与否的判定没有变化。这些比例来自发布说明，本刊未复跑。GitHub published_at 为 2026-11-14T08:24:22Z。

browser-use 1.0.5 is a regular release. The notes say each run adds one low-effort request to the user's own model, which checks the run against the task and fills result.judgement with success, failure_reason, description, prompt_injection_detected, bot_block_or_captcha_detected and gotchas. judge_context= supplies the criteria and judge=False turns judging off; the 0.x use_judge and ground_truth options work again. The judge sees the trace, the run's last screenshots and the final page, unless use_vision=False. It writes gotchas when the site rejected input, errored, blocked or rate-limited the agent, including on a run judged successful, for example when a form requires phone numbers in (###) ###-#### format. The notes report 13 real runs, each judged 3 times: gotchas appeared on 15 of 15 verdicts where the site pushed back (6 of 15 before) and on 2 of 24 clean runs, with success verdicts unchanged. These rates come from the release notes and were not rerun by TUJL. GitHub published_at is 2026-11-14T08:24:22Z.

Qwen Code 夜间版更新托管会话、飞书投递与代理循环

A Qwen Code nightly updates managed sessions, Feishu delivery and the agent loop

Qwen Code 发布预发布标签 v0.27.2-nightly.20261113.6f754be654。发布说明中的变更包括：托管代理可把客户端文件系统登记进托管会话；长的频道回复按有序的多段投递来安排；飞书自定义机器人增加 webhook 投递；AUTO 分类器改为判断用户授权，并避免对 HTTP URL 做 UNC 查找；AgentCore 与 OpenTUI 的每一轮都放进一次 runAgentLoop 调用；快速分类器超时改由会话模型复核；并恢复原生的 Anthropic 未签名思考历史。同版依赖修复的说明写明涉及 MCP、DOMPurify 与压缩请求解析，以及 qs、URI 与 Hono，本刊未核对通告编号。功能范围来自该夜间构建的发布说明，本刊未安装运行。GitHub published_at 为 2026-11-14T11:31:46Z。

Qwen Code published the pre-release tag v0.27.2-nightly.20261113.6f754be654. Changes named in the notes include registering client filesystems into managed-agent sessions, planning long channel replies as ordered multi-segment deliveries, and adding Feishu custom-bot webhook delivery. The AUTO classifier now judges user authorization and avoids UNC lookups for HTTP URLs. Each AgentCore round and each OpenTUI round runs in one runAgentLoop call. Fast-classifier timeouts are reviewed with the session model, and native Anthropic unsigned thinking history can be recovered. Dependency fixes in the notes name MCP, DOMPurify and compressed-request parsing, plus qs, URI and Hono; TUJL did not check advisory identifiers. This scope comes from the nightly release notes, and TUJL has not installed the build. GitHub published_at is 2026-11-14T11:31:46Z.

llama.cpp 预发布 b12385 补上 Qwen2-VL 的 NVFP4 前馈缩放

llama.cpp pre-release b12385 applies Qwen2-VL NVFP4 feed-forward scales

ggml-org 发布 llama.cpp 预发布构建 b12385，位于 v1.0.0 之后。发布说明写明，qwen2vl 计算图此前把 ffn_up、ffn_gate 与 ffn_down 的缩放传成 NULL，因此通用流程装入的逐张量 NVFP4 缩放从未生效，模型输出为垃圾：CUDA 上困惑度约为 1e6，CPU 上为 NaN。此构建把这些缩放传给 build_ffn，与 qwen2 的做法一致，并写明修复问题 #32101。上述困惑度与 NaN 来自发布说明对缺陷的描述，本刊未复测。GitHub published_at 为 2026-11-14T18:48:53Z。

ggml-org published llama.cpp pre-release build b12385, after v1.0.0. The notes say the qwen2vl graph passed NULL for the ffn_up, ffn_gate and ffn_down scales, so the per-tensor NVFP4 scales loaded by the generic pass were never applied and the model produced garbage: perplexity of about 1e6 on CUDA and NaN on CPU. This build passes those scales to build_ffn, as qwen2 does, and says it fixes issue #32101. The perplexity and NaN figures are the notes' description of the bug and were not rerun by TUJL. GitHub published_at is 2026-11-14T18:48:53Z.

LiteLLM v1.108.9 is a regular release on the 1.108 long-term line. The notes say this Docker image is signed with cosign using the key introduced in commit e82a3c6, and they show verification against that commit and against the tag. Changes backported to lts/1.108.x include preserving mixed reasoning and answers on the Responses path, accepting s3:// media sources in Bedrock Converse, sending reasoning_effort to Foundry Kimi K3 and keeping its reasoning_content, attaching caller-identity labels on Vertex requests, keeping cache_control breakpoints on the chat-to-Responses bridge, using Foundry project and resource /openai/v1 Responses bases, adding Vercel AI Gateway decision models, and mapping OpenAI vector-store search filters to Bedrock. This scope comes from the release notes and was not reproduced by TUJL in a gateway. GitHub published_at is 2026-11-14T22:00:02Z.
