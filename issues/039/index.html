Qwen Code 0.25.1 加入持久后台任务与执行记录

Qwen Code 0.25.1 adds durable background tasks and execution records

Qwen Code 发布 0.25.1 稳定版，为 Managed Agent 加入后台 Shell 与 Monitor，在把工具结果返回模型前保存参数、回执和检查点；Agent 与 Goal 协调工具改为按需发现。版本也提供实验性的 Kubernetes CSI 运行时。 Kubernetes CSI 运行时仍属实验功能；以上为项目发布说明，非独立实测结论。

Qwen Code released stable version 0.25.1 with background Shell and Monitor capabilities for Managed Agents. Tool parameters, receipts and checkpoints are recorded before results return to the model, while Agent and Goal tools are discovered on demand. An experimental Kubernetes CSI runtime is also included. The Kubernetes CSI runtime is experimental. These are project release notes, not independently tested results.

LiteLLM 1.105.0 把决策 API、护栏与路由接入网关

LiteLLM 1.105.0 brings decision APIs, guardrails and routing into the gateway

LiteLLM 1.105.0 稳定版加入 OpenAI 格式的 /v1/decisions 与独立的 /v1/systemone 接口，并提供决策模型护栏和基于已部署决策模型的自动路由配置。管理员可为护栏设置是非问题、阈值及拦截或仅记录行为。 保存新式路由配置前需升级所有代理副本，回滚前需转换或移除这些配置。护栏效果取决于模型和配置，不能据此宣称已解决提示注入。

LiteLLM 1.105.0 adds an OpenAI-format /v1/decisions endpoint, a separate /v1/systemone route, decision-model guardrails and auto-router setup using an existing decision-model deployment. Administrators can configure yes/no checks, thresholds, and block or log-only behavior. Upgrade every proxy replica before saving deployment-backed routers; convert or remove those configurations before rollback. Guardrail effectiveness depends on the model and configuration.

llama.cpp 预发布扩展 Gemma-4 OpenCL GPU 解码

llama.cpp prerelease expands Gemma-4 OpenCL GPU decoding

llama.cpp 发布 b11559 预发布构建，为 Gemma-4 E4B 与 E2B 启用 OpenCL GPU 解码，并优化 DK64 GQA8 和 DK128 GQA4 解码路径。这是推理软件与硬件适配更新，不是 Gemma-4 模型首次发布。发布说明未给出可泛化的提速数字；效果仍取决于具体硬件与模型配置，本刊未独立运行复测。

llama.cpp publishes prerelease build b11559, enabling OpenCL GPU decoding for Gemma-4 E4B and E2B and optimizing DK64 GQA8 and DK128 GQA4 decoding paths. This updates inference-software and hardware compatibility; it is not a Gemma-4 model launch. The release notes do not establish a general speedup. Results depend on hardware and model configuration, and we have not independently run or reproduced them.
