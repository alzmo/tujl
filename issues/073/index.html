Open WebUI v0.13.4 connects a user's own computer through Tether and sandboxes the terminal

Open WebUI v0.13.4 为正式发布。发布说明把 Tether 写成对 Direct Connections 的替换。用户在 Tether 应用里添加的模型，来自 Ollama、LM Studio 或任何兼容 OpenAI 的服务器，以及 OpenAPI 与 MCP 工具服务器和 Open Terminal 服务器，只会出现在该用户自己的模型选择器、加号菜单里的工具列表和终端菜单中，无论从哪台设备打开所连接的 Open WebUI。Open WebUI 经 Tether 访问它们，地址、命令和密钥留在用户的计算机上。这需要 Tether 0.1.14 或更新版本；MCP 服务器、工具服务器和终端需要 0.1.16。工具服务器和终端还需要打开 ENABLE_TOOL_SERVERS。标识与 Open WebUI 里已有模型相同的 Tether 模型会保持隐藏（#34397）。Tether 0.1.13 或更新版本可以把终端锁进沙箱：在 macOS 和支持的 Windows 设备上，Open Terminal 及其启动的程序，包括编程代理，只能接触用户选定的一个文件夹；除非打开网络访问，否则离线运行，并且不接受传入连接，不需要 Docker、虚拟机或管理员权限。若沙箱无法强制执行，终端保持停止，而不是在没有沙箱的情况下运行；沙箱打开时，浏览器和桌面控制保持关闭。本地 MCP 可以按 stdio 命令经 Tether 0.1.16 或更新版本启动，不需要 mcpo 这类代理，也不需要开放端口；说明写明这些本地命令以用户自己的账户权限运行，位于 Tether 工作区沙箱之外。连接 Terminals 0.4.0 或更新版本后，对连接有写权限的人可以从消息输入的终端菜单创建终端，并选择所有人共用一台机器，或按用户、对话或模型各用一台，同时设置镜像、CPU、内存、存储、网络配置、环境变量、起始目录和安装脚本。启动和停止需要 Terminals 0.4.1 或更新版本；起始目录和安装脚本需要镜像里的 Open Terminal 0.17.7 或更新版本；网络配置来自管理员用 TERMINALS_NETWORK_PROFILES 定义的项目。编程代理可以像其他模型一样在对话里使用。Hermes、Antigravity、GitHub Copilot、Goose 和 Qwen Code 加入已有的 Codex、Claude Code、Cursor、Grok、OpenCode、Cline、Gemini CLI 和 Pi；用 OPEN_TERMINAL_ACP_AGENTS 加到 Open Terminal 的其他 ACP 代理，在终端上安装并登录后也可以使用。工具权限里的 Auto 让 Codex、Claude Code 和 Grok 自行批准常规动作，只把它们升级的请求交出来。高级参数里的推理力度现在也用于 Claude Code、Pi，以及提供力度等级的 ACP 代理，例如 OpenCode；所选等级对该模型不可用时会报错停止。回复可以重新生成，较早的消息可以编辑。分叉或克隆的代理对话从原处接上：Codex 从该点继续自己的会话，其他代理根据至此的对话重新开始，代理已经做出的文件改动保留。Claude Code 要到 0.17.20 之后的下一版 Open Terminal 才会继续自己的会话，在那之前会要求先更新。新代理，以及对 Claude Code 和 Grok 的 Auto，需要 Open Terminal 0.17.19 或更新版本；Claude Code、Pi 和 ACP 代理的力度需要 0.17.9 或更新版本（#34167）。说明还写明，一次到达、含 300 个代码块的回复现在在 9 秒内显示，而不是超过两分钟（#34495）。同页还有默认关闭的可视化工具、默认关闭的视频生成，以及大量其他添加与修复；本条不把那些条目改写成单独核过的行为。上述范围来自这一标签的发布说明，本刊未安装或运行这一构建。GitHub published_at 为 2026-11-17T14:46:26Z。

Open WebUI v0.13.4 is a regular release. The notes describe Tether as the replacement for Direct Connections. Models added in the Tether app, from Ollama, LM Studio or any OpenAI-compatible server, plus OpenAPI and MCP tool servers and Open Terminal servers, show up only for that user in the model selector, the Tools list of the + menu and the terminal menu, on any device used to open a connected Open WebUI. Open WebUI reaches them through Tether, so addresses, commands and keys stay on the user's computer. This needs Tether 0.1.14 or later; MCP servers, tool servers and terminals need 0.1.16. Tool servers and terminals also need ENABLE_TOOL_SERVERS turned on. A Tether model whose ID matches a model already in Open WebUI stays hidden (#34397). Tether 0.1.13 or later can lock the terminal into a sandbox: on macOS and supported Windows devices, Open Terminal and everything it launches, coding agents included, can touch only the one folder the user picks. It runs offline unless Network access is turned on, accepts no incoming connections, and needs no Docker, virtual machine or administrator setup. If the sandbox cannot be enforced, the terminal stays stopped instead of running without it. Browser and desktop control stay off while the sandbox is on. Local MCP servers can be launched as stdio commands through Tether 0.1.16 or later, with no proxy such as mcpo and no port to open. The notes say those local commands run with the user's own account access, outside Tether's workspace sandbox. With Terminals 0.4.0 or later connected, anyone with Write access to the connection can create a terminal from the message input's terminal menu, choose whether everyone shares one machine or each user, chat or model gets its own, and set its image, CPU, memory, storage, network profile, environment variables, start directory and a setup script. Start and Stop need Terminals 0.4.1 or later. The start directory and setup script need Open Terminal 0.17.7 or later in the terminal's image. Network profiles are the ones an administrator defined with TERMINALS_NETWORK_PROFILES. Coding agents now work in chat much like any other model. Hermes, Antigravity, GitHub Copilot, Goose and Qwen Code join Codex, Claude Code, Cursor, Grok, OpenCode, Cline, Gemini CLI and Pi. Any other ACP agent added to Open Terminal with OPEN_TERMINAL_ACP_AGENTS works once it is installed and signed in on the terminal. Auto for tool permissions lets Codex, Claude Code and Grok approve routine actions themselves and pass on only what they escalate. Reasoning effort in the advanced parameters now also applies to Claude Code, Pi and ACP agents that offer effort levels, such as OpenCode, which stop with an error when the chosen level is not offered for the model. Replies can be regenerated and earlier messages edited. A forked or cloned agent chat picks up where the original left off: Codex continues its own conversation from that point, other agents start over from the chat so far, and file changes the agent already made stay. Claude Code continues its own conversation with the next Open Terminal release after 0.17.20, and until then asks for an update. The new agents, and Auto for Claude Code and Grok, need Open Terminal 0.17.19 or later. Effort for Claude Code, Pi and ACP agents needs 0.17.9 or later (#34167). The notes also say a reply with 300 code blocks that arrives at once now shows in 9 seconds instead of more than two minutes (#34495). The same page includes a visualizations tool that is off by default, video generation that is off by default, and many further additions and fixes; this item does not restate those entries as separately checked behavior. pydantic-ai v2.70.0 为正式发布。发布标题写着 v2.70.0 (2026-11-17)，计时以 GitHub published_at 为准。072期已经记录过 v2.69.0；本条记录的是比较范围 v2.69.0...v2.70.0 里的后一个标签。安全说明转述两则高危公告，修复都写在 pydantic-ai-harness 0.70.0。GHSA-m4cr-m4qc-9hh3：在 strip_ansi=True 时，Harness 的 ToolOutputLimits 用一种按行长呈二次时间的模式去掉 ANSI 转义序列，因此一条几百千字节、含有许多未结束转义序列的工具结果，可能把事件循环占住几十秒到几分钟。受影响的是把 strip_ansi 设为 True（0.13.0 之前名为 OverflowingToolOutput）、并且运行攻击者能够影响其输出的工具的人。GHSA-5m5q-5qj4-gx9h：Harness 秘密遮盖中的 jwt 模式在所扫描文本的长度上呈二次时间回溯，因此几百千字节的特制文本可能把事件循环占住几十秒到几分钟。受影响的是在攻击者能够影响的文本上使用 redact_secrets 或 secret_data()，并且用到默认就包含的 jwt 模式的人。说明写明修复后的模式不再匹配标头段含有 -eyJ 的 JWT。本条只转述影响范围和修复版本，不提供构造输入的方法。功能条目包括：加入 OpenAI 的 gpt-6.2-sol 与 gpt-6.2-astra（#13760）；StreamGuardrail 在调用方看到之前筛查每一段流式文本、思考和工具调用（#13667）；PruneToolResults 让模型把刚收到的工具结果换成摘要（#13634）；ToolSearch 用于搜索前的延迟（#13139）；PlaywrightBrowser 可以按每次运行为 CDP 端点做准备，并附着到默认上下文（#13555）；把 service_tier 转发给 xAI，并在 provider_details 中记录实际服务的等级（#13524）；HuggingFaceModelSettings 增加 huggingface_logprobs 与 huggingface_top_logprobs，并在 provider_details 中返回 logprobs（#6855）；Skills 在 read_files=True 时可以读取已加载技能打包的文件，并替换 ${SKILL_DIR} 占位符（#13678）；父级可以用 check_task 与 DelegationTasks.snapshot() 查看仍在运行的后台委派（#13647）。兼容性说明中的条目包括：在 OpenAIChatModel 把工具发给已开启推理的 GPT-6 模型之前抛出 ModelRequestRejectedError（#12264）；OpenRouter 上的 qwen/qwen3.8-flash 在推理时拒绝强制工具选择，因此回退到 auto，或抛出 ModelRequestRejectedError（#12262）。发布说明还列出大量其他修复与重命名，本条不把那些条目改写成单独核过的行为。上述范围来自这一标签的发布说明，本刊未运行该库。GitHub published_at 为 2026-11-17T22:44:30Z。

pydantic-ai v2.70.0 is a regular release. The release title reads v2.70.0 (2026-11-17); this item times it by GitHub published_at. Issue 072 already recorded v2.69.0; this item records the later tag in the compare range v2.69.0...v2.70.0. The security notes restate two high-severity advisories, and both fixes are stated for pydantic-ai-harness 0.70.0. GHSA-m4cr-m4qc-9hh3: with strip_ansi=True, the Harness ToolOutputLimits capability removed ANSI escape sequences with a pattern that took time quadratic in the length of a line, so a tool result of a few hundred kilobytes with many unterminated escape sequences could occupy the event loop for tens of seconds to minutes. Someone is affected if they set strip_ansi=True (named OverflowingToolOutput before 0.13.0) and run tools whose output an attacker can influence. GHSA-5m5q-5qj4-gx9h: the jwt pattern in the Harness secret redaction backtracked in time quadratic in the length of the text it scanned, so a few hundred kilobytes of crafted text could occupy the event loop for tens of seconds to minutes. Someone is affected if they use redact_secrets or secret_data() with the jwt pattern, which is included by default, on text an attacker can influence. The notes say the fixed pattern no longer matches a JWT whose header segment contains -eyJ. This item restates the affected scope and the fixed version, and it does not provide a way to construct an input. Feature items include adding OpenAI's gpt-6.2-sol and gpt-6.2-astra (#13760); StreamGuardrail screening each streamed text, thinking and tool-call part before the caller sees it (#13667); PruneToolResults so the model can replace a tool result it just received with a summary (#13634); ToolSearch for pre-search deferral (#13139); PlaywrightBrowser provisioning its CDP endpoint per run and attaching to the default context (#13555); forwarding service_tier to xAI and recording the served tier in provider_details (#13524); adding huggingface_logprobs and huggingface_top_logprobs to HuggingFaceModelSettings and returning logprobs in provider_details (#6855); letting Skills read a loaded skill's bundled files with read_files=True and substitute ${SKILL_DIR} placeholders (#13678); and letting a parent check a running background delegation with check_task and DelegationTasks.snapshot() (#13647). Items in the compatibility notes include raising ModelRequestRejectedError before OpenAIChatModel sends tools to GPT-6 models with reasoning on (#12264), and falling back to auto or raising ModelRequestRejectedError for forced tool choice on OpenRouter's qwen/qwen3.8-flash, which rejects forcing while reasoning (#12262). The notes list many further fixes and renames; this item does not restate those entries as separately checked behavior. This scope comes from that tag's release notes, and TUJL has not run the library. GitHub published_at is 2026-11-17T22:44:30Z.
