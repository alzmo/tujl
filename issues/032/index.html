LOCAL INFERENCE · 维护者发布Strata / GitHub · 2026.10.04 · 12:32 UTC

Strata 0.1.39 增加并行请求与 Responses API，明确性能取舍

Strata 0.1.39 adds parallel requests and a Responses API with explicit trade-offs

Strata 发布0.1.39，新增可选并行会话及面向 Codex 的无状态 Responses API，并修复设置内存预算时的提示词处理退化。维护者在 RTX 5070 上测得四路请求使最后一路的等待从11.2秒降至1.8秒，但总解码速度降低11%。这些是项目自测，不能外推到所有硬件；旧显卡与 Intel Arc 路径仍属实验支持，部分设备未由维护者实机验证。接口不支持 previous_response_id、托管工具或推理摘要。

Strata releases 0.1.39 with optional parallel conversations, a stateless Responses API for Codex, and a fix for prompt-processing regressions under a RAM budget. In maintainer tests on an RTX 5070, four concurrent requests reduced the last request’s wait from 11.2 to 1.8 seconds while lowering aggregate decoding speed by 11%. These are project-run measurements, not guarantees across hardware. Older GPU and Intel Arc paths remain experimental, with some devices untested by maintainers. The API excludes previous_response_id, hosted tools and reasoning summaries.

AGENT CONNECTORS · 作者说明inboxmcp 作者 / Hugging Face · 2026.10.04 · 23:26 UTC

inboxmcp 公开邮箱智能体设计：只读收信，按连接记录处理进度

inboxmcp details read-only email access and per-agent processing checkpoints

inboxmcp 作者发布设计说明：托管 MCP 服务通过只读 IMAP 收集新邮件，让用户自己的智能体依据个人规则决定是否提醒；批次领取与完成确认分开，未确认的邮件可在中断后继续处理。作者称工具不能发送、删除或移动邮件，并将邮件正文与用户规则分离。只读并不消除读取敏感邮件或提示注入的风险；这些是作者的实现与安全主张，未经本刊独立审计。当前不解析附件、不提供全文搜索，也不导入启用收集之前的邮件。

The maker of inboxmcp publishes design notes for a hosted MCP service that collects new mail through read-only IMAP and lets a user’s own agent decide when to notify them. Separate batch-claim and completion steps leave unconfirmed messages available after interruption. The author says tools cannot send, delete or move mail, and email content is separated from owner instructions. Read-only access does not remove sensitive-data or prompt-injection risks; these implementation and security claims have not been independently audited here. Attachment parsing, full-text search and importing mail from before collection began are not supported.
