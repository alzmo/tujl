OpenAI 说明 Codex 如何在用户控制的文件与网络限制内运行本机命令

OpenAI explains how Codex runs local commands inside filesystem and network limits the user controls

OpenAI 发布《Inside the Codex sandbox》。文章页只标出日历日期 November 18, 2026，没有时刻；计时以 openai.com 新闻 RSS 中该文的 pubDate 为准，为 Wed, 18 Nov 2026 08:00:00 GMT。该文写明，Codex 可以在用户的计算机上运行命令，范围限于用户控制的文件系统与网络限制，通过权限配置（permission profiles）设置，覆盖 macOS、Linux 与 Windows。以 Git 仓库为工作区根目录时，内置的 :workspace 配置允许在工作区内写入，同时把 .git 与 .codex 等目录保持为只读，因此 Codex 可以修改源代码，而不必为每一次改动请求许可，但不能直接修改 .codex/config.toml，也不能直接修改 .git/hooks 下的 Git hooks。它允许较宽的文件系统读取，但仍受用户已有的操作系统权限约束。该文自己指出其中的取舍：机器上其他位置的敏感文件，例如含有 API 密钥的配置文件，仍可能保持可读。该配置关闭网络访问，从而阻断直接上传和数据外传，同时也阻断合法的依赖下载，除非另外授予访问。该文写明，这些限制能挡住一大类不良行为，但并不能挡住所有伤害，并给出例子：代理可以把恶意代码注入本地已安装的包，例如 node_modules/prettier；这类改动可能不会出现在 git status 里，因为 node_modules 常常被 Git 忽略。该文把沙箱写成可复用的原语，并写明 codex sandbox 命令可以让其他工具沿用同一套按权限配置执行命令的机制。防御纵深，以及训练与对齐能让模型按用户意图使用这些权限，都是 OpenAI 自己的说法。该文还写明各平台的落实方式：macOS 通过 /usr/bin/sandbox-exec 使用 Seatbelt；Linux 由内部辅助程序 codex-linux-sandbox 组合 bubblewrap 与 seccomp-bpf；在兼容的 Windows 设备上，Codex 支持基于 MXC（Microsoft eXecution Container）的沙箱，并写明正在用它替换原有的 Windows 沙箱。本条只转述该文写出的边界，不把这些机制写成已经独立验证的隔离保证。RSS pubDate 为 Wed, 18 Nov 2026 08:00:00 GMT。

OpenAI published Inside the Codex sandbox. The article page shows only the calendar date November 18, 2026, with no time of day. This item times it by the pubDate on its openai.com news-RSS entry, Wed, 18 Nov 2026 08:00:00 GMT. The post says Codex can run commands on the user's machine inside filesystem and network limits the user controls, configured through permission profiles, on macOS, Linux and Windows. With a Git repository as the workspace root, the built-in :workspace profile allows writes within the workspace while keeping directories such as .git and .codex read-only, so Codex can edit source without permission for every change, but cannot directly change .codex/config.toml or Git hooks under .git/hooks. It allows broad filesystem reads, subject to the user's existing OS permissions. The page itself notes the tradeoff that sensitive files elsewhere on the machine, such as config files containing API keys, may remain readable. The profile disables network access, which blocks direct uploads and exfiltration, and also blocks legitimate dependency downloads unless additional access is granted. The post says these restrictions prevent a large class of bad behavior, but not all harm, and gives an example: the agent could inject malicious code into a locally installed package such as node_modules/prettier, and that change might not appear in git status because node_modules is often ignored by Git. The post describes the sandbox as a reusable primitive, and it says the codex sandbox command lets other tools run commands under the same permission-profile mechanism. Defense in depth, and the claim that training and alignment help the model use that access in accordance with the user's intent, are OpenAI's own statements. The post also states how the limits are applied: on macOS, Codex uses Seatbelt through /usr/bin/sandbox-exec; on Linux, an internal helper named codex-linux-sandbox combines bubblewrap and seccomp-bpf; on compatible Windows devices, Codex supports an MXC (Microsoft eXecution Container) sandbox and says it is replacing the existing Windows sandbox with one that uses MXC. This item restates the boundaries the post states and does not treat those mechanisms as an independently verified isolation guarantee. The RSS pubDate is Wed, 18 Nov 2026 08:00:00 GMT.
