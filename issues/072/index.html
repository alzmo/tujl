Unsloth v0.1.918-beta 加入默认关闭的计算机操作，并给出图像解码时间

Unsloth v0.1.918-beta adds computer use, off by default, and states an image decode time

Unsloth 发布标签 v0.1.918-beta。GitHub 发布记录没有把它标为预发布，本条按该记录计时，同时保留标签名里的 beta。发布说明把计算机操作（computer use，beta）、模型选择器、连接改版与训练改动写在同一标签下，并写明此版也包含 Unsloth Studio 与训练上的改动。计算机操作让本地模型看到屏幕，并在 macOS、Windows 与 Linux 上控制鼠标和键盘；说明写明它默认关闭。支持本地 GGUF、safetensors 与 MLX 视觉模型，以及已连接的提供方。第一次动作、切换应用和可能有风险的动作都要先批准；被拦截的应用仍然不可访问，用户可以随时收回控制。MCP 菜单在 Blender 之外加入 Unity、Unreal Engine、Godot、Figma 与 Roblox；说明写明 Figma 为只读。MiniMax-H3-Image 支持 GGUF、FP8 与 INT8，以及 LoRA 训练。GGUF 经 stable-diffusion.cpp 在 CPU、Mac、较小的 GPU 和 AMD 上运行；FP8 与 INT8 权重面向 NVIDIA。自动精度按硬件选择 INT8、FP8 或 BF16。说明给出一张 2048px 图像在 A100 80GB 上的解码时间为 0.28 秒，而不是 2.82 秒。Gemma 4 12B 训练在新的注意力内核上快 1.4–2.6 倍；新的 INT8 注意力内核使 FLUX.3 Klein 的渲染在受支持的 GPU 上提高 15–23%。连接画廊新增 9 个提供方：xAI、NVIDIA NIM、Perplexity、Cohere、Vercel AI Gateway、Azure OpenAI、Amazon Bedrock、Google Vertex AI 与 SGLang。Qwen3.8-Flash-Next 与 DeepSeek-V4.1 的 GGUF 可以把 Engram 表换成更小或无损的表。说明给出计算机操作指南和权重页面的链接，本刊未把那些页面当作额外的一手来源核对。上述时间与速度来自发布说明，本刊未复跑。GitHub published_at 为 2026-11-16T15:04:23Z。

Unsloth published the tag v0.1.918-beta. GitHub does not mark the release as a pre-release, so this item times it from that record while keeping the beta in the tag name. The notes put computer use (beta), the model picker, the connections redesign and training changes under the same tag, and they say the release also includes changes across Unsloth Studio and training. Computer use lets local models see the screen and control the mouse and keyboard on macOS, Windows and Linux; the notes say it is off by default. It supports local GGUF, safetensors and MLX vision models, plus connected providers. Approval is required before the first action, before switching apps and before potentially risky actions. Blocked apps stay inaccessible, and the user can take control back at any time. The MCP menu adds Unity, Unreal Engine, Godot, Figma and Roblox alongside Blender; the notes say Figma is read-only. MiniMax-H3-Image supports GGUF, FP8 and INT8, plus LoRA training. GGUF runs through stable-diffusion.cpp on CPU, Macs, smaller GPUs and AMD; FP8 and INT8 weights are for NVIDIA. Automatic precision selects INT8, FP8 or BF16 from the hardware. The notes say a 2048px image decodes in 0.28s instead of 2.82s on an A100 80GB. Gemma 4 12B training is 1.4–2.6x faster with the new attention kernels. New INT8 attention kernels improve FLUX.3 Klein rendering by 15–23% on supported GPUs. The provider gallery adds nine providers: xAI, NVIDIA NIM, Perplexity, Cohere, Vercel AI Gateway, Azure OpenAI, Amazon Bedrock, Google Vertex AI and SGLang. Qwen3.8-Flash-Next and DeepSeek-V4.1 GGUFs can swap in a smaller or lossless Engram table. The notes link a computer-use guide and weight pages; TUJL did not treat those pages as further primary sources. These times and speed figures come from the release notes and were not rerun by TUJL. 分布式训练 / Distributed trainingAccelerate · GitHub Release · 2026.11.17 05:01:44 · 北京时间 / UTC+8

Accelerate 1.16.0 要求 Python 3.11 与 PyTorch 2.6，并改进 FSDP 加载

Accelerate 1.16.0 requires Python 3.11 and PyTorch 2.6, and improves FSDP loading

Accelerate v1.16.0 为正式发布。发布说明写明，库更广泛地使用 torch.accelerator，以便已注册的 PyTorch 后端不必在各处再走一条设备专用分支；现有集成在需要兼容时仍保留各自的原生 API。其中包含通过 torch-tpu 使用单芯片 TPU 的初步改进，说明写明更广的 TPU 支持仍在进行。单芯片 torch-tpu 的修复涉及绑定权重、safetensors 加载、内存报告与 FP16 校验（#4570）。accelerate launch 在 Ctrl+C 或 SIGTERM 时会退出并清理子进程（#4573）。FSDP 的修复针对省内存加载，包括与 Transformers 在非零 rank 上把模型载入 meta 设备的兼容；FSDP1 会在初始化替换 meta 参数时重新接上优化器引用，FSDP2 在映射到分片替换时区分这些参数（#4576）。FSDP2 可以在没有优化器的情况下准备模型，从而允许在训练前调用 Trainer.evaluate()（#4519）。此版要求 Python 3.11+ 与 PyTorch 2.6+（#4459、#4461），移除 PiPPy 与 MS-AMP 集成（#4462、#4463），并移除已弃用的 FP8RecipeKwargs；TorchAO 改用 AORecipeKwargs，Transformer Engine 改用 TERecipeKwargs（#4464）。上述范围来自发布说明，本刊未独立验证启动器信号、FSDP 加载或版本门槛。GitHub published_at 为 2026-11-16T21:01:44Z。

Accelerate v1.16.0 is a regular release. The notes say the library uses torch.accelerator more broadly, so registered PyTorch backends do not need a separate device-specific branch throughout the library. Existing integrations keep their native APIs where compatibility requires them. The changes include initial single-chip TPU use through torch-tpu, and the notes say broader TPU support remains in progress. Single-chip torch-tpu fixes cover tied weights, safetensors loading, memory reporting and FP16 validation (#4570). accelerate launch exits and cleans up child processes on Ctrl+C or SIGTERM (#4573). FSDP fixes address RAM-efficient loading, including compatibility with Transformers loading models onto the meta device on nonzero ranks. FSDP1 reconnects optimizer references when initialization replaces meta parameters, and FSDP2 distinguishes those parameters when mapping them to sharded replacements (#4576). FSDP2 can prepare a model without an optimizer, so Trainer.evaluate() can run before training (#4519). This release requires Python 3.11+ and PyTorch 2.6+ (#4459, #4461), removes the PiPPy and MS-AMP integrations (#4462, #4463), and removes the deprecated FP8RecipeKwargs. TorchAO uses AORecipeKwargs, and Transformer Engine uses TERecipeKwargs (#4464). This scope comes from the release notes. TUJL has not independently verified launcher signals, FSDP loading or the version floor. GitHub published_at is 2026-11-16T21:01:44Z.

推理服务 / Inference servervLLM · GitHub Release · 2026.11.17 07:22:00 · 北京时间 / UTC+8

vLLM 0.34.0 默认启用可扩展 KV 缓存，并移除 Model Runner V1

vLLM 0.34.0 turns extensible KV cache on by default and removes Model Runner V1

vLLM v0.34.0 为正式发布。发布说明写明此版有 1,061 个提交，来自 412 位贡献者，其中 120 位是新贡献者。要点包括 10 个新模型，可扩展 KV 缓存默认开启，以及 Model Runner V1 被移除、Model Runner V2 成为唯一的 GPU 运行器。升级表写明：设置 VLLM_USE_V2_MODEL_RUNNER=0 会在启动时失败（#63373）；默认 --block-size 从 16 改为 64，要保留旧行为需传入 --block-size 16，ROCm 分页注意力仍使用 16（#63231）；可扩展 KV 缓存默认开启，gpu_memory_utilization 默认为 1.0，要保留旧的容量估算可传入 --gpu-memory-utilization 0.9 或 --no-enable-extensible-kv-cache（#56492）；ROCm 7.2 构建不再发布，改用 ROCm 10.0 的 wheel 与镜像（#61939）；要求 huggingface_hub >= 2.0.0，同时要求 tokenizers >= 0.23.3 与 timm >= 1.0.30（#64779）；fp_quant 检查点不再能加载（#65230）；Marlin W4A8 被移除，说明改为使用 --quantization humming，并用 VLLM_HUMMING_INPUT_QUANT_CONFIG 代替 VLLM_MARLIN_INPUT_DTYPE（#65542）；Keye-VL 与 Keye-VL-1.5 被移除（#64287）。新模型表中的 Mistral Large 4 写明总参数 1T、活跃 52B，提供 FP8 与 NVFP4，可在 NVIDIA Blackwell/Hopper 与 AMD MI350 上运行（#64534）。同表还列出 MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe、Ripple-65B Preview、ZAYA1、Unlimited-OCR-2、LFM3 及其视觉与音频变体、Canary-1B-v2、Ming3-ASR 与 Parakeet TDT。在 CUDA 与 ROCm 上，KV 缓存按预热之后实际剩余的内存来定大小。说明举例：MiniMax-M3 在 H200 上从 433k token 增到 672k token；代价是部分模型的逐 token 解码时间可能上升，在并发 128 时部分 H200 模型的 TPOT 增加 6–18%。性能表写明：Step5 的 NVFP4 MoE 在 TRTLLM-Gen 上、于 4 张 GB200 的解码最高到 1.95 倍（#65152）；GLM-5.3-Flash 的 DeepGEMM FP8 MegaMoE 输出吞吐相对 DEP4 为 1.6 倍（#60895）；默认的、张量并行下按 token 分片的稀疏 MLA 预填充，在 GB200 上使 GLM-5.3 于 32K–128K 的 TTFT 快 1.24–1.40 倍（#63956）。CUDA 13.0 的安装行是 pip install vllm；ROCm 10.0 使用 https://wheels.vllm.ai/rocm/0.34.0/rocm100 作为额外索引。说明里的 XPU 安装行旁边有一条仍待确认的审阅注释，本条不把那一行当作已经确定的安装方法。上述缓存长度与加速倍数来自发布说明，本刊未复跑。GitHub published_at 为 2026-11-16T23:22:00Z。

vLLM v0.34.0 is a regular release. The notes say this version has 1,061 commits from 412 contributors, 120 of them new. Highlights are 10 new models, extensible KV cache on by default, and the removal of Model Runner V1 so Model Runner V2 is the only GPU runner. The upgrade table says setting VLLM_USE_V2_MODEL_RUNNER=0 now fails at startup (#63373); the default --block-size changes from 16 to 64, --block-size 16 keeps the old behavior, and ROCm paged attention still uses 16 (#63231); extensible KV cache is on by default and gpu_memory_utilization defaults to 1.0, while --gpu-memory-utilization 0.9 or --no-enable-extensible-kv-cache keeps the old sizing (#56492); ROCm 7.2 artifacts are no longer published, and the notes point to ROCm 10.0 wheels and images (#61939); huggingface_hub >= 2.0.0 is required, along with tokenizers >= 0.23.3 and timm >= 1.0.30 (#64779); fp_quant checkpoints no longer load (#65230); Marlin W4A8 is removed, and the notes say to use --quantization humming with VLLM_HUMMING_INPUT_QUANT_CONFIG instead of VLLM_MARLIN_INPUT_DTYPE (#65542); Keye-VL and Keye-VL-1.5 are removed (#64287). In the new-model table, Mistral Large 4 is listed as 1T total and 52B active, with FP8 and NVFP4, running on NVIDIA Blackwell/Hopper and AMD MI350 (#64534). The same table also lists MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe, Ripple-65B Preview, ZAYA1, Unlimited-OCR-2, LFM3 with its vision and audio variants, Canary-1B-v2, Ming3-ASR and Parakeet TDT. On CUDA and ROCm, the KV cache is sized from memory actually free after warmup. The notes give an example: MiniMax-M3 on H200 goes from 433k tokens to 672k tokens. The trade-off is that per-token decode latency can rise on some models, with TPOT up 6–18% on some H200 models at concurrency 128. The performance table says Step5 NVFP4 MoE on TRTLLM-Gen reaches up to 1.95× decode on 4×GB200 (#65152); GLM-5.3-Flash DeepGEMM FP8 MegaMoE reaches 1.6× output throughput versus DEP4 (#60895); default token-sharded sparse-MLA prefill under tensor parallelism makes GLM-5.3 TTFT 1.24–1.40× faster at 32K–128K on GB200 (#63956). The CUDA 13.0 install line is pip install vllm. ROCm 10.0 uses https://wheels.vllm.ai/rocm/0.34.0/rocm100 as an extra index. The XPU install line in the notes sits next to a reviewer note that it still needs confirmation, so this item does not treat that line as a settled install method. These cache lengths and speed multiples come from the release notes and were not rerun by TUJL. GitHub published_at is 2026-11-16T23:22:00Z.

pydantic-ai v2.69.0 is a regular release. The release title reads v2.69.0 (2026-11-16); this item times it by GitHub published_at. Items in the compatibility notes include folding RequestInput into HandleDeferredToolCalls, whose handler can take a resume token (#13285); GoogleModel support for Gemini 4 Hydrogen under the name gemini-4-hydrogen (#13299); DetectLoops checking loops in streamed thinking, text and tool-call arguments (#12222); Advisor accepting native= and local=, with mode deprecated (#13149); raising ModelQuotaExceededError for Anthropic's tier spend cap and user-set spend limits (#13269); and mapping Mistral Large 4 thinking levels to its low, medium and high reasoning_effort values (#12876).
